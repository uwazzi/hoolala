- 2026-10-27 (WP2): Email sign-in through Resend's HTTP API in new `src/channels/email.ts` (a channel, like `telegram.ts`; sends the magic link only). Without `EMAIL_API_KEY` on localhost the link is printed to the dev console; nowhere else is an email or link logged.

Rate limits in KV: 3 links per email per 15 min, 10 per IP per hour, keyed by hashes.

- 2026-10-28 (WP5): The meet QR is a link (`/meet?code=XXXXXX`) opened with the phone's own camera, not an in-app scanner: no camera permission (the Permissions-Policy keeps `camera=()`), no scanner library; the 6-character code (no 0/O/1/I/L) is the typed fallback. Codes are stored hashed and last 10 minutes. Only a signal's owner and an accepted responder can meet; two responders on the same signal never saw each other's names, so they can't. Outsiders always get the same `not_found` as a wrong code, whatever the code's state. STAY IN TOUCH lives at `POST /api/meet/:id/stay-in-touch` (the plan said `/api/stay-in-touch/:signalId`) because the person is identified by the confirmed meet, not by the signal; it answers `{ok:true}` whatever the other chose.
- 2026-10-28 (WP6): `GET /api/live` is public and cached 30 s: hellos (both-confirmed `here` interactions since 27 Oct), connection rate (distinct accepted signals that have a confirmed interaction / distinct accepted signals), check-ins that worked (ok / all attempts; the first-try metric needs per-session tracking and waits for WP9), facts confirmed this week, hellos per place listed by name, never ranked. SAMPLE places aren't excluded yet because they don't exist yet (WP9). QR encoder `uqr` added (no dependencies, about 5 KB gzipped).
- 2026-10-28 (WP20, revised): Real towns and villages instead of the fixed five-city list, which showed Lausanne to anyone outside those cities. When someone shares location, the server asks OpenStreetMap's Nominatim (live, zoom 14, point rounded to 5 decimals, identifying User-Agent, no key) which village or town the point is in; only the name comes back and nothing about the person is kept. Places store that name in `city` plus an accent- and case-free `city_key` that search compares (migration 0004, which also turns the old city ids into names). Search by name takes any town as free text, pre-filled from the phone. The five cities stay as the fallback when Nominatim is slow or down, and as suggestions in the town field. This supersedes the first WP20 entry about cities.
- 2026-10-28 (WP9): SAMPLE place for judges: "SAMPLE: The Demo Café" (no coordinates, so never in nearby; city "Sample"), checked into from anywhere with code DEMO or ARRIVE's "Try the SAMPLE place". Sample Sophie (`users.is_sample`) is kept checked in with one open signal (capacity 3, topic rotating every 30 min) by `ensureSample`, run idempotently by the cron and on every visit. She accepts I'M CURIOUS at once and replies "We're at the spot"; when a judge starts MEET her side joins and agrees, so the judge only taps WE MET. Nothing at a sample place counts on the Live page: interactions, accepted signals and check-in attempts at `places.is_sample = 1` are excluded (migration 0005). Real people at the sample place can see each other's signals there, labelled by the SAMPLE banner.
- 2026-10-28 (WP0, Muse Spark): Meta Model API confirmed from Switzerland with our key: base `https://api.meta.ai/v1`, `Authorization: Bearer`, model `muse-spark-1.3` in Standard mode for every function (Meta's guidance: Spark for latency-sensitive classification and tight tool loops; Wonder is for long agent runs at 3 to 5 times the price). Not Contributor mode: it lets Meta train on prompts and responses, which would include people's topics, replies and FIND ME findings, and it is capped at 150 RPM. Endpoints: Chat Completions (`/chat/completions`) for screening, translation, structured output (`response_format.json_schema`, `strict: true`) and function tools (`tool_choice` must be `auto`; `parallel_tool_calls` defaults to true); the Responses API (`/responses`) for web search (`tools: [{type: "web_search"}]`, citations as `url_citation` annotations), which Chat Completions does not offer. `reasoning_effort` per function (`minimal` for SCREEN IT; `none` is refused). Test calls 28 Oct: structured screening with a FR→EN translation in 2.2 s and 335 tokens; web search in 7.4 s, which needs `max_output_tokens` around 1,500 (400 was cut off). Prices: $1.25 in / $4.25 out per 1M tokens, cached input $0.15, web search $2.50 per 1,000; limits 3,000 RPM and 4M TPM per team. `META_API_BASE` and `MUSE_SPARK_MODEL` are plain vars in both wrangler configs; `META_API_KEY` is a Worker secret only (docs/SECRETS.md).
- 2026-10-28 (WP23, SCREEN IT): `src/llm/client.ts` is the only way to Muse Spark: off unless `LLM_ENABLED=true` and the key and base are set; strict JSON schema plus our own validator; a timeout per function; never throws (failure means the caller's fallback); one `llm_calls` row with token counts only; `writeWorking` for CHECK IT. SCREEN IT runs only after the code rules pass, on topics and curious lines (4 s, `minimal` effort): it may add a refusal (shown with our fixed message for its category), never overrules a code refusal, and never rewrites; the stored and displayed text is always what the person typed, with the model's EN or FR translation kept separately in `signals.translation` and shown under it as "AI / translation". On timeout, invalid output or with the model off, the code rules' approval stands (`screening_verdict = approved_by_rules`). AI is on for staging only; production keeps `LLM_ENABLED=false` until a promote is accepted.
- 2026-10-28 (WP23, SUGGEST IT): One Responses API call with `web_search` (`max_tool_calls: 1`, `include: ["web_search_call.results"]`, approximate location CH plus the place's town) and a strict JSON answer; the input is place name, kind, town, Zurich time and spots only, never anything about the person. A real call showed the JSON arrives in the last message after a preamble, reasoning used about 1,100 tokens at `low` effort (budget 2,500, timeout 15 s, about 7 s observed), and the model cited a site's homepage instead of the event page it had found. So `src/rules/grounding.ts` keeps an event idea only if its citation matches a URL the search returned in that call (compared without tracking parameters or trailing slashes), and strips unreturned citations from general ideas. Every kept idea then passes the code rules and SCREEN IT. Results are cached per place per hour in KV (place data only), so one search serves everyone there. Off or failing: three fixed ideas for the time of day, labelled IDEA. Ideas only fill the text box; nothing is posted without the person's tap. Limit 10 requests an hour per person.
- 2026-10-28 (pipeline): Production ran code that needed migration 0005 before the database had it (the Live page crashed with Cloudflare 1101, and HERE, I'M CURIOUS and the DEMO check-in failed) until the owner applied it by hand. Cause: deploy workflows deployed code but never migrated, so every release depended on a manual step. Fix: each deploy workflow applies D1 migrations right before deploying, so a failed migration stops the release; the smoke test now reads `/api/live` (a database-backed endpoint) so a mismatch fails the run. Needs D1 Edit on the CI token.
